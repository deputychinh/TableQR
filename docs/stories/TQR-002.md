# TQR-002: Same-origin `/api`, problem details, redacted request logs

- Release: v0.2.0 · Status: doing · Owner: Claude (deliver-loop)
- Spec/design: `docs/delivery/001-qr-table-ordering/design.md` (API shape), ADR 0002 §1, `docs/security.md` (logging, limits)

## Story

As a developer of every later item, I want the API under `/api` on the web app's origin, one error format and safe request logs, so that features need no CORS, clients handle errors by `code`, and logs never leak tokens or personal data.

INVEST: Independent ☑ Negotiable ☑ Valuable ☑ (enabler) Estimable ☑ Small ☑ Testable ☑

## Acceptance criteria

| Id             | Given                                                                                                                 | When                  | Then                                                                                                                                                          |
| -------------- | --------------------------------------------------------------------------------------------------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AC1            | the API runs                                                                                                          | `GET /api/health`     | 200 `{status:'ok',db:'up'}`; `GET /health` (old path) → 404                                                                                                   |
| AC2 (negative) | any unknown route                                                                                                     | it is requested       | 404 `application/problem+json` with `type`, `title`, `status`, `code: NOT_FOUND`, no stack trace                                                              |
| AC3 (error)    | a handler throws an unexpected error                                                                                  | the request completes | 500 problem with `code: INTERNAL`, generic title, no internal message; the error is logged with the request id                                                |
| AC4 (limit)    | a JSON body larger than 32 kB                                                                                         | it is posted          | 413 problem `code: PAYLOAD_TOO_LARGE`                                                                                                                         |
| AC5            | any request                                                                                                           | it completes          | one JSON log line with request id, method, **route pattern** (never the raw path, which can hold QR tokens), status, duration; response header `x-request-id` |
| AC6 (security) | an object logged with `cookie`, `authorization`, `password`, `phone`, `guestName`, `token` keys (any depth, any case) | it is redacted        | those values are `[REDACTED]`, others unchanged, input not mutated                                                                                            |
| AC7            | the web dev server or preview build                                                                                   | the page loads        | the health status comes from `/api/health` on the same origin (no CORS), on `localhost` and `127.0.0.1`                                                       |

## Non-functional

- Security: no stack or internal message in responses (A10); log redaction (A09); body limit (A10).
- Performance: logging is one line per request, no body logging.

## Out of scope

- Origin check / CSRF (TQR-004), security headers for production (before first deploy).

## References

- RFC 9457 Problem Details for HTTP APIs (`init-project/references/api-design.md`).
- OWASP Logging Cheat Sheet — exclude session ids, access tokens, personal data (`references/security.md` A09).

## Design

- API: `app.setGlobalPrefix('api')`; global `ProblemFilter` maps `DomainError` (code + status) and Nest `HttpException` to problems; anything else → 500 `INTERNAL`. Error codes in `src/common/errors/error-code.enum.ts`.
- Logging: `RequestLogMiddleware` → `Logger` port writing JSON to stdout; `redact()` pure function.
- Web: Vite `server.proxy` and `preview.proxy` `/api` → `http://127.0.0.1:${TQR_API_PORT ?? 3310}`; `getJson` uses relative `/api`. CORS removed from the API.
- Data: none.
