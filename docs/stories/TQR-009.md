# TQR-009: Platform admin — suspend / reactivate a restaurant

- Release: v0.2.0 · Status: review · Owner: Claude (deliver-loop)
- Spec: S16 (AC54), design.md (`restaurants.status`, `/api/admin/restaurants/*`), ADR 0003 §5, `docs/security.md`

## Story

As the platform admin, I want to suspend a restaurant, so that abuse can be stopped at once — and reactivate it when it is sorted out.

INVEST: Independent ☑ (after TQR-004) Negotiable ☑ Valuable ☑ Estimable ☑ Small ☑ Testable ☑

## Acceptance criteria (spec ids)

| ---------------- | ------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| AC54             | an active restaurant with signed-in staff   | the platform admin suspends it                               | its sessions are deleted at once (next request → 401); staff sign-in with the right password → 403 `RESTAURANT_SUSPENDED` "Nhà hàng tạm ngưng" |

| S16-list         | the admin                                   | `GET /api/admin/restaurants?limit&offset`                    | newest first with owner email and account count; `limit` 1–200 (default 50), unknown query keys → 422                                          |
| S16-role (neg.)  | an owner or staff session                   | any admin endpoint                                           | 403 `FORBIDDEN`; the admin (no restaurant) gets 403 on restaurant endpoints such as `/api/staff`                                               |
| S16-cli          | an operator with database access            | `TQR_ADMIN_PASSWORD=… npm run admin:create -- --email a@b.c` | a `platform_admin` user without a restaurant; weak password / taken email → exit 1; neither email nor password is ever printed                 |

## Design

- API (`src/admin/`): `GET /api/admin/restaurants`, `POST /api/admin/restaurants/:id/suspend`, `POST …/reactivate` (idempotent, 200 with the restaurant). `@Roles('platform_admin')`. Suspend updates `restaurants.status` and deletes `auth_sessions` of that restaurant in one transaction.
- Identity: `AuthService.login` checks the restaurant status after the password check; `authenticate` already refuses suspended restaurants. Reusable `assertRestaurantActive` (pure, `identity/domain/restaurant-status.ts`) and `RestaurantStatusService` (exported by `IdentityModule`).
- CLI: `services/api/scripts/create-platform-admin.ts`, run by Node's built-in TypeScript (`npm run admin:create`); it imports only dependency-free files (`schema.ts`, `password.ts`, `pg-error.ts`, with `.ts` extensions — `rewriteRelativeImportExtensions` in `tsconfig.json` lets tsc accept them).
- Web: `/quan-tri` in `StaffShell` — restaurant cards with status chip (icon + word), suspend / reactivate through `ConfirmSheet` spelling out the consequence, "Xem thêm" paging; sign-in shows "Nhà hàng tạm ngưng…" for `RESTAURANT_SUSPENDED`.
