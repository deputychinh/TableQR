# TQR-011: Guest check-in / join table session

- Release: v0.3.0 · Status: done · Owner: Claude (agent, ordering branch)
- Spec: S6 (AC17–AC21), AC54 for guest pages, AC3 (isolation); design.md (Data: `table_sessions`, `guest_devices`), ADR 0002 §3, ADR 0003, `docs/design-system.md`

## Story

As a guest, I want to start my table by scanning its QR code and saying how many we are, so that the restaurant knows our party — and my friends' phones join the same table without asking again.

INVEST: Independent ☑ (after TQR-007, 008) Negotiable ☑ Valuable ☑ Estimable ☑ Small ☑ Testable ☑

## Non-functional

- Security: `tqr_guest` = 256-bit random (base64url), only its SHA-256 in `guest_devices`; `HttpOnly; SameSite=Lax; Path=/; Max-Age=24h`, `Secure` except on plain-http localhost; the tenant comes only from the QR token (check-in) or the cookie; unknown cookie → 401 `GUEST_NOT_CHECKED_IN`; strict body schema (unknown keys → 422); non-GET guest calls pass the Origin guard.
- UX: party size with the shared `NumberStepper` (big −/+) and one primary button; the expired, not-found, suspended and wait states use `EmptyState` with a plain next step.

## Design

- API: `POST /api/g/session {qrToken, partySize?}` → 201 opened / 200 joined `{session, opened}`, or 409 `PARTY_SIZE_REQUIRED` (with `maxPartySize`) / `WAIT_FOR_STAFF`; `GET /api/g/session` → restaurant, table, session, orders; `POST /api/sessions`, `PATCH /api/sessions/:id` (floor roles).
- Code: `services/api/src/service/{service.module,guest.controller,floor.controller,sessions.service,guest.cookie}.ts`; `domain/ordering.ts` (party bounds), `domain/service-errors.ts`. One transaction per check-in with `SELECT … FOR UPDATE` on the table row.
- Web: `web/src/features/ordering/pages/GuestTablePage.vue` now owns `/t/:qrToken`. The TQR-007 placeholder page and its "Thực đơn sắp có" copy are removed; the expired and not-found strings are reused from `guestTable.*`.

Screenshots (opened and reviewed): `docs/delivery/001-qr-table-ordering/evidence/ordering-check-in-{390,1180}-{light,dark}.png`.

Decisions: a phone that already belongs to the open session gets no new device row. A phone of a closed session that scans again joins (or opens) the table's next session with a new cookie; its old cookie stays refused (AC21). For a suspended restaurant `GET /api/g/t` still answers 404 (TQR-007 decision), while check-in answers 403 `RESTAURANT_SUSPENDED`.
