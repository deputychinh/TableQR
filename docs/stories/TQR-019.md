# TQR-019: Cashier confirm, close session, pay before cooking

- Release: v0.4.0 · Status: review · Owner: Claude (billing worktree)
- Spec: S13 (AC44–AC47), AC13, AC15; ADR 0005, ADR 0006, `docs/security.md` (payment path ASVS L2, bank-change banner)

## Story

As a cashier, I want to confirm a transfer or cash against a bill and close the table, so that I know who paid, the table is free for the next party, and pay-before-cooking orders go to the kitchen the moment the money arrives.

## Design

- `BillingService.pay`: locks the session row, then `update bills set status='paid' … where status='open'` (compare-and-set); 0 rows → re-read → `ALREADY_PAID` or `BILL_SUPERSEDED`. In the same transaction `releaseAfterPayment(tx, tenant, sessionId, coveredUntil = bill.created_at, paidAt)` releases pay-before orders requested up to the bill's issue time (ADR 0005: queue time = payment confirmation).
- `closeSession`: locks the session, computes what is due, enforces the reason, supersedes the open bill, cancels held / awaiting-payment orders, closes, deletes `guest_devices` of the session (ADR 0002 §3), publishes, logs `session_closed` (no reason text).
- `GET /api/bills/overview` (owner, cashier): open sessions with total, paid, due, latest bill (+ who confirmed), `bankConfigured`, `bankChangedAt`, `bankChangedRecently` (`isBankChangeRecent`, 24 h).
- Web `/thu-ngan` (StaffShell; replaces the TQR-005 placeholder in `roles/routes.ts`, owner may open it too): one card per table (status chip, total, due, code), "Lấy hoá đơn", "Đã nhận chuyển khoản" / "Đã nhận tiền mặt" through `ConfirmSheet` repeating table, amount and code (and the memo to look for), "Đóng bàn" with a reason field when money is due; reloads on every floor-stream event.

## Review round 1 (independent security review, 6.5/10 correctness → fixed)

- Paid-but-never-released: a bill reused at the same amount after its orders changed left the new pay-before order held. Now, when a payment leaves nothing due, every `awaiting_payment` order of the session is released; otherwise only those placed before the bill (test › a reused bill whose orders changed …).
- Closing a session supersedes its open bill and cancels `held` / `awaiting_payment` orders with their pending items; confirming a bill of a closed session → 409 `SESSION_CLOSED` (test › closing supersedes …).
- Totals are summed in SQL over every billable line; the 500-line cap applies to the displayed list only (test › totals every billable line …).
- A stored bank account that cannot be encoded no longer fails the bill or a committed payment: the bill shows "Thanh toán tại quầy" and logs `vietqr_unbuildable` (test › a stored account banks would refuse …).

Follow-ups (not in this item): per-session throttle on `POST /api/g/bill` (a guest can supersede a code while a transfer is in flight — the cashier then sees `BILL_SUPERSEDED`; no rate limiter exists in the API yet); optional `expectedAmountVnd` on pay; **TQR-012 must lock the `table_sessions` row `FOR UPDATE` when placing an order** so an order cannot commit with `requested_at` before a bill it was not part of.
