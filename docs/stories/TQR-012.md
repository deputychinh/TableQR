# TQR-012: Guest menu and ordering (idempotent, price check)

- Release: v0.3.0 · Status: done · Owner: Claude (agent, ordering branch)
- Spec: S7 (AC22–AC25), AC12, AC13, AC6; design.md (Data: `orders`, `order_items`), ADR 0003, ADR 0004, ADR 0005, `docs/design-system.md`

## Story

As a guest, I want to pick dishes on my phone and send them to the kitchen, so that I don't wait for a waiter — and a shaky connection never sends my order twice.

INVEST: Independent ☑ (after TQR-006, 011) Negotiable ☑ Valuable ☑ Estimable ☑ Small ☑ Testable ☑

## Non-functional

- Kitchen fields copied per item: `station_id` (menu item), `is_main` (category), `session_opened_at`, name and price snapshots. Realtime: `order.status` to `floor` and `session:<id>`; each released item sends `item.status {itemId, status: waiting, version}` to `station:<stationId>`, all inside the writing transaction.
- UX: menu by category with "Thêm", then big −/count/+; "hết món" dishes stay visible without a button; a sticky bottom bar shows "n món · total" with "Giỏ hàng (n)" and "Gửi món"; the cart sheet has a note per dish; the cart survives a reload (`sessionStorage`); the idempotency key comes from `crypto.randomUUID`, with a `getRandomValues` fallback for plain-http shop networks.

## Design

- API: `GET /api/g/menu` (the session's restaurant, same shape as `/api/g/r/:slug/menu`), `POST /api/g/orders` (`Idempotency-Key` header, body `{lines:[{menuItemId, quantity, priceVnd, note?}]}`).
- Code: `orders.service.ts` `place()` locks the session, looks up the idempotency key, prices the cart (`priceCart`), reads the rules, runs `checkOrder`, inserts order and items and publishes. Pure helpers in `domain/ordering.ts` (`CART_LIMITS`, `priceCart`, `parseIdempotencyKey`, `initialOrderStatus`). Web: `features/ordering/{cart.ts, composables/useGuestOrdering.ts, components/{GuestOrdering,CartSheet,ItemQuantity}.vue}`; `GuestMenuList` gained an `action` slot; `api/client.ts` gained `postJsonWithHeaders`.
