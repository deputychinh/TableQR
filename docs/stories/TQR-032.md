# TQR-032: Graceful API shutdown with open event streams

- Release: unreleased · Status: done · Owner: Claude
- Spec: ADR 0004 (realtime), ADR 0010 (this change)

## Story

As whoever restarts or deploys the API, I want it to stop at once even while kitchen iPads and guest phones hold event streams open, so that `nest --watch` restarts and production restarts never hang.

Found in review (2026-11-08): `app.enableShutdownHooks()` was on, but Nest closes the HTTP server with `server.close()`, which waits for every open connection; a browser (or a proxy) keeps an SSE connection open indefinitely, so `app.close()` never resolved.

## Acceptance criteria

| Id  | Given                                                                 | When                                   | Then                                                                |
| --- | --------------------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------- |
| G1  | staff floor, kitchen station, guest order and guest bill streams open | `app.close()` (SIGTERM, watch restart) | it resolves within 2 s                                              |
| G2  | the same streams                                                      | shutdown begins                        | each gets `event: bye` as its last event and the server ends it     |
| G3  | shutdown has begun                                                    | a stream opens                         | it gets `bye` and ends at once (no new open connection to wait for) |
| G4  | a client that gets `bye`                                              | —                                      | it reconnects with its backoff (TQR-031), status `reconnecting`     |

## Design

`StreamGate` implements `BeforeApplicationShutdown` (run before Nest disposes the HTTP adapter) and aborts an `AbortController`; `openStream` takes its signal as `stop`, sends `bye`, unsubscribes and ends the response (once). No `forceCloseConnections`: other requests still finish normally.
