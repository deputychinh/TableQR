# TQR-006: Menu — stations, categories (main-dish flag), items, availability

- Release: v0.2.0 · Status: review · Owner: Claude (deliver-loop)
- Spec: S2 (AC5–AC7), S1 AC3 (isolation), glossary "Main dish" and "Station"; design.md (Data: `stations`, `categories`, `menu_items`); ADR 0003; `docs/design-system.md`

## Story

As a restaurant owner, I want to set up kitchen stations, menu categories (marking the main-dish ones), dishes with prices, and switch a dish to "hết món" in one tap, so that guests see an accurate menu and every order reaches the right station.

INVEST: Independent ☑ (after TQR-004) Negotiable ☑ Valuable ☑ Estimable ☑ Small ☑ (ordering is TQR-012, the kitchen screen TQR-014) Testable ☑

## Decisions (decide-and-record)

- **Roles**: owner writes everything; owner, cashier, waiter and kitchen read; **kitchen may toggle availability** because the cooks are first to know a dish ran out. Platform admin (no tenant) gets 403.
- **Default station** is created lazily on the first `GET /api/menu` (not at sign-up), so identity stays unaware of the menu context; a race is absorbed by the unique `(restaurant_id, lower(name))` index + `ON CONFLICT DO NOTHING`. The last station cannot be deleted, so an item always has somewhere to go.
- **Foreign ids in the body** (`categoryId`/`stationId` of another restaurant) answer 404 like foreign path ids (ADR 0003 §4), enforced by the composite FKs `(restaurant_id, category_id)` / `(restaurant_id, station_id)`; their violation (23503) maps to 404, and on delete to `CATEGORY_NOT_EMPTY` / `STATION_NOT_EMPTY` (race-free, no count-then-delete).
- FKs are `NO ACTION` (checked at statement end), not `RESTRICT`, so deleting a restaurant still cascades.
- **Guest menu by slug** (`GET /api/g/r/:slug/menu`) is public and read-only: the menu is public information. Suspended or unknown restaurants answer 404 (the "Nhà hàng tạm ngưng" page is TQR-009). Ordering (TQR-012) will resolve the tenant from the table token and must refuse `orderable: false` items (AC6 second half).
- Price is validated by zod `int().min(1000).max(100000000)` reading the domain constants, and again by a DB `CHECK`; the web form pre-checks with the same limits and reads "35.000", "35 000" and "35000" alike (a comma is a decimal mark → "not whole").
- Menu-specific error codes live in `src/menu/menu.errors.ts` (not the shared enum) so parallel items do not collide on one file.
- **OwnerShell**: the content now scrolls between the header and the bottom bar. With a long menu the sticky bottom bar covered rows, which axe reported as `target-size` (and WCAG 2.4.11 Focus Not Obscured). Two CSS properties changed; no visual change on short pages.

## Non-functional

- Security: tenant from the session only; strict zod bodies (unknown fields 422); malformed ids 404; Origin check on writes (existing guard); guest payload exposes no station ids.
- Accessibility: switches are `role="switch"` named "Còn món: <dish>"; icon buttons named "Sửa món …", "Đưa nhóm … lên"; sheets are the shared `<dialog>` `BaseSheet` (Escape or backdrop closes, explicit "Huỷ" button); "Hết món" is icon + word + strike-through, never colour alone; targets ≥ 44 px.
- UX: one primary action ("Thêm món"); the empty state leads to "Thêm món đầu tiên", which first asks for a category when there is none, then opens the item form; prices `35.000 ₫` (Intl vi-VN); optimistic availability switch rolls back with a plain message.

## Design

- API (`services/api/src/menu/`): `GET /api/menu` → `{stations, categories:[{…, items}]}`; `POST/PATCH/DELETE /api/menu/stations[/:id]`; `POST/PATCH/DELETE /api/menu/categories[/:id]`, `POST /api/menu/categories/:id/move {direction}` → `{categories}`; `POST/PATCH/DELETE /api/menu/items[/:id]`; `PUT /api/menu/items/:id/availability {available}`; `GET /api/g/r/:slug/menu`.
- Data (migration `0001_menu`): `stations(id, restaurant_id, name, late_after_minutes 1..120 default 15)`, `categories(id, restaurant_id, name, is_main, sort_order)`, `menu_items(id, restaurant_id, category_id, station_id, name, price_vnd CHECK 1000..100000000, description, available, created_at, updated_at)`; `unique(restaurant_id, id)` on each, unique `(restaurant_id, lower(name))` on stations and categories, composite FKs from items.
- Domain: `domain/{price,names,station,ordering,menu-tree}.ts` (limits, name normalisation, swap-for-move, grouping and the guest projection); DTOs in `dto/menu.dto.ts`.
- Web (`web/src/features/menu/`): `MenuPage` (list on phone, list + stations column on iPad), `MenuPreviewPage` ("Xem như khách"), `ItemSheet`, `CategorySheet`, `StationSheet`, `MenuItemRow`, `StationPanel`, `GuestMenuList`, `useMenu`, `api`, `errors`, `price`, `locale`. Uses main's shared `BaseSheet`, `ConfirmSheet`, `EmptyState`, `ErrorState`, `LoadingState`, `SelectField` (from TQR-007/008); adds `ToggleSwitch`, `StatusChip`, `TextAreaField`, `NumberField`.
