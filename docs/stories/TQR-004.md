# TQR-004: Restaurant sign-up, staff sign-in/out, sessions, throttling

- Release: v0.2.0 · Status: doing · Owner: Claude (deliver-loop)
- Spec: S1 (AC1–AC4), design.md (Data: restaurants, users, auth_sessions, login_attempts), ADR 0002, ADR 0003, `docs/design-system.md`

## Story

As a restaurant owner, I want to register my restaurant myself and sign in on any device, so that I can start setting it up without a sales call — and so that nobody else can get into my restaurant.

INVEST: Independent ☑ (after TQR-002) Negotiable ☑ Valuable ☑ Estimable ☑ Small ☐ → kept as one item because sign-up without sign-in/out is not demo-able; staff accounts are TQR-005 · Testable ☑

## Acceptance criteria (spec ids)

| Id                 | Given                                                    | When                                                                       | Then                                                                                                                                           |
| ------------------ | -------------------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| AC1                | no account                                               | the owner submits restaurant name (2–80 chars), email, password ≥ 10 chars | the restaurant and its owner user are created, the owner is signed in (`tqr_staff` cookie) and lands on `/quan-ly` showing the restaurant name |
| AC1a (boundary)    | the form                                                 | name of 1 or 81 chars, invalid email, password of 9 chars, unknown fields  | 422 `VALIDATION_FAILED` with the failing `fields`; the form shows the message under each field; nothing is created                             |
| AC2 (negative)     | an email already registered (any letter case)            | someone signs up with it                                                   | 409 `EMAIL_TAKEN`, "Email đã được dùng" under the email field; nothing created                                                                 |
| AC2a (concurrency) | two sign-ups with the same email at the same moment      | both are sent                                                              | exactly one succeeds, the other gets 409                                                                                                       |
| AC3 (isolation)    | owner A signed in                                        | A asks for `/api/me`                                                       | only A's restaurant is returned; the tenant comes from the session, never from the request                                                     |
| AC4 (negative)     | 10 failed sign-ins for one email within 15 minutes       | an 11th attempt (even with the right password)                             | 429 `LOGIN_BLOCKED` "Thử lại sau 15 phút"; after the window passes sign-in works again                                                         |
| AC4a               | wrong password or unknown email                          | sign-in                                                                    | the same 401 `INVALID_CREDENTIALS` text for both (no account enumeration)                                                                      |
| AC5                | a signed-in user                                         | signs out                                                                  | the session row is deleted, the cookie cleared, `/api/me` → 401                                                                                |
| AC6 (security)     | a non-GET request whose `Origin` is not the app's origin | it is sent with a valid cookie                                             | 403 `BAD_ORIGIN`, nothing changes (CSRF, ADR 0002 §4)                                                                                          |
| AC7                | an expired or unknown session cookie                     | any staff endpoint                                                         | 401 `UNAUTHORIZED`; the web app sends the user to `/dang-nhap` keeping the page they wanted                                                    |

## Non-functional

- Security: scrypt (N=2^17, r=8, p=1) hashes; 256-bit session tokens, only SHA-256 stored; cookie `HttpOnly; SameSite=Lax; Path=/; Secure` unless the request is plain-http localhost; session rotated on sign-in; 12 h sliding expiry; constant-time compare; emails lower-cased; no email/password in logs (redaction patterns).
- Accessibility: labels above inputs, errors linked with `aria-describedby`, focus moves to the first invalid field, password show/hide toggle with a name, autocomplete attributes (`email`, `new-password`, `current-password`).
- UX (owner rule): one primary button per form, plain Vietnamese, friendly empty welcome on `/quan-ly`, works one-handed on a phone and on an iPad.

## Out of scope

- Staff accounts and roles (TQR-005), password reset by email (backlog), MFA (backlog).

## Design

- API: `POST /api/auth/signup` {restaurantName, email, password} → 201 `{user, restaurant}` + cookie; `POST /api/auth/login` {email, password} → 200; `POST /api/auth/logout` → 204; `GET /api/me` → 200 `{user:{id,email,role}, restaurant:{id,name,slug}}`. Validation with zod (`.strict()`), errors 422 with `fields: [{path, code}]`.
- Data (migration `0000_identity`): `restaurants(id uuid pk, name, slug unique, status, rules jsonb default '{}', created_at)`, `users(id, restaurant_id fk, email unique (lower), password_hash, role, disabled_at, created_at)`, `auth_sessions(token_hash pk, user_id fk on delete cascade, restaurant_id, expires_at, created_at, last_seen_at)`, `login_attempts(id, email, attempted_at, succeeded)` + index (email, attempted_at). Sign-up in one transaction; email uniqueness by unique index (23505 → `EMAIL_TAKEN`).
- Code: `src/identity/{identity.module,auth.controller,auth.service,session.guard,origin.guard}.ts`, `domain/{password,session-token,slug,throttle}.ts`, `repositories/*.ts` with `TenantId` brand (`src/common/tenant.ts`); a `Clock` port for throttle windows (tests move time).
- Web: design-system components first (`AppShell`, `BaseButton`, `FormField`, `PasswordField`, `ErrorState`, `Toast`) in `src/components/`; pages `/dang-ky`, `/dang-nhap`, `/quan-ly` (owner home, empty welcome with next steps); `useSession` store (Pinia) + router guard; layouts compact (phone) and expanded (iPad).
