# TQR-017: Tenant isolation and role e2e matrix

- Release: v0.5.0 · Status: review · Owner: Claude (deliver-loop)
- Spec: AC3 (tenant isolation), AC15 (roles); ADR 0003; docs/security.md (BOLA/BFLA rows)

## Story

As every restaurant on the platform, I want certainty that no other restaurant — and no staff member in the wrong role — can read or change my data, so that sharing one system is safe.

## Acceptance criteria

| Id  | Given                                                                                           | When                                             | Then                                                                                               |
| --- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| I1  | every staff endpoint in `test/support/role-matrix.ts`                                           | each of the 5 roles calls it                     | allowed roles pass, every other role gets 403 `FORBIDDEN`; no session → 401 (existing AC15 matrix) |
| I2  | a guarded route with no `@Roles`                                                                | any role calls it                                | 403 (deny by default)                                                                              |
| I3  | every matrix row that names a row of restaurant A (path id or body id) and is allowed to owners | the owner of restaurant B calls it with A's ids  | 404, and nothing changes                                                                           |
| I4  | the sweep                                                                                       | a new endpoint with an id is added to the matrix | it is swept automatically (no per-endpoint test to remember)                                       |

Guest-side isolation (a guest cookie of table/restaurant A reaching B) is covered per feature: `ordering.e2e-spec.ts` (phone of table A scanning table B), `guest-stream.e2e-spec.ts`, `billing.e2e-spec.ts`, `realtime.e2e-spec.ts` (streams of B never see A's events).

## Design

`test/roles.e2e-spec.ts`: an intruder owner signs up a second restaurant; `isolationCases` = matrix rows allowed to owners whose path or body references a fixture id (`/:…` in the path, `":":…` in the serialised body placeholders); each is called with the intruder's cookie and must answer 404 (streams: the opening status). The per-IP and per-user test limits are already raised in the e2e setup.
