# TQR-008: House rules and bank account settings

- Release: v0.2.0 · Status: done · Owner: Claude (deliver-loop)
- Spec: S4 (AC12; AC13 is enforced in TQR-019), design.md (Domain `house-rules.ts`, Data `restaurants`), ADR 0003, ADR 0006, `docs/security.md` (tampering with the bank account), `docs/design-system.md`

## Story

As an owner, I want my own house rules and the bank account guests pay into, so that the system works the way my restaurant works ("quy cách vận hành riêng").

INVEST: Independent ☑ (after TQR-004) Negotiable ☑ Valuable ☑ Estimable ☑ Small ☑ Testable ☑

## Non-functional

- Security: owner-only bank details (deny-by-default `@Roles`), Origin check on `PUT`, zod `.strict()` everywhere, audit line without the account number, bank columns all-or-none by a check constraint.
- Accessibility: radio cards are a `fieldset` + `legend` with native radios; steppers are `role="spinbutton"` with min/max/now/valuetext and named −/+ buttons (Arrow/Home/End keys); errors linked by `aria-describedby`, focus on the first invalid field; the confirm sheet is a modal dialog with focus kept inside and returned on close; axe serious/critical = 0 on iPhone and iPad.
- UX (owner rule): plain Vietnamese with one sentence per choice; one primary button, sticky at the bottom (above the bottom navigation on phones); live preview of how the account will look to guests; "Đã lưu" tells the owner that new orders use the new settings.

## Out of scope

- Enforcing the rules: pay-before-cooking (AC13, TQR-019), anomaly check (TQR-013), booking slots (TQR-020), self check-in vs staff opens (TQR-011). The cashier's 24-hour "bank changed" banner (TQR-019). Late threshold per station (menu, TQR-006).
- A rules history table: not needed while every order carries its own snapshot (see Design).

## Design

- API (`services/api/src/settings/`): `GET /api/restaurant/settings` (owner) → `{rules, rulesUpdatedAt, bank: {bin, bankName, accountNumber, accountName} | null, bankChangedAt, banks}`; `PUT /api/restaurant/settings` (owner) `{rules, bank | null}` — full replace, same answer; `GET /api/restaurant/rules` (owner, cashier, waiter, kitchen) → `{rules, rulesUpdatedAt, bankConfigured, bankChangedAt}`. The bank list comes from the API (one source of truth); the web keeps only the stepper bounds.
- Domain: `domain/house-rules.ts` (zod schema, `RULE_LIMITS`, `DEFAULT_RULES`, `readStoredRules` = defaults deep-merged under the stored JSON so rules added later get their default, `sameRules`, `snapshotRules`, `rulesAt`), `domain/banks.ts` (20 banks with NAPAS BIN), `domain/account-name.ts` (normalise, patterns, `maskAccountNumber`).
- Data (migration `0001_settings`): `restaurants.rules_updated_at`, `bank_bin`, `bank_account`, `bank_account_name`, `bank_changed_at` + check `restaurants_bank_all_or_none`. Opening hours live inside `rules.booking.openingHours` (not a separate `opening_hours` column as design.md sketched) so one validated JSON and one version cover every rule. The update locks the row (`SELECT … FOR UPDATE`) and moves `rules_updated_at` / `bank_changed_at` only when the value really changed — saving an untouched form makes no new version and no false bank warning.
- **AC12 — how later items use it.** `rules_updated_at` is the version of `restaurants.rules`. TQR-012 must, in the same transaction that inserts an order, read the restaurant's rules (`readStoredRules`) and store `snapshotRules(rules, rulesUpdatedAt)` in `orders.rules_snapshot jsonb`. Everything that later judges that order (anomaly check TQR-013, pay-before-cooking release TQR-019, bill TQR-018) reads `order.rules_snapshot.rules`, never `restaurants.rules`. `rulesAt(versions, at)` states the rule precisely — the latest version whose `effectiveFrom ≤ at`, a change at the same instant already applies — and is what the snapshot tests prove.
- Web (`web/src/features/settings/`): `SettingsPage.vue` inside `OwnerShell` with sections Thanh toán / Mở bàn / Duyệt đơn (+ thresholds) / Đặt bàn (+ slot, opening hours) / Tài khoản nhận chuyển khoản; `components/OpeningHoursEditor.vue`, `components/BankAccountSection.vue`; `model.ts` (types, early checks, field-path → message), `settings-api.ts`, `routes.ts`, `locale.ts`. New shared components in `web/src/components/`: `RadioCardGroup`, `NumberStepper`, `ConfirmSheet`, `SelectField`, `LoadingState`, `ErrorState`; `FormField` gained an `inputmode` prop.
