# TQR-022: Production security headers and X-Powered-By removal

- Release: unreleased (after v0.5.0) · Status: review · Owner: Claude (parallel agent, branch of main e2007c8)
- Spec: `docs/security.md` (Baseline controls, "Before first deploy"), ADR 0002 (one origin, `/api` proxied), OWASP ASVS 5.0 V3.4 (browser security headers)

## Story

As the operator about to put TableQR on the internet, I want every API response and every SPA page to carry the production security headers, and the rate limits to see the real client address behind a reverse proxy, so that framing, sniffing, injected scripts and spoofed addresses are stopped by default.

INVEST: Independent ☑ Negotiable ☑ Valuable ☑ Estimable ☑ Small ☑ Testable ☑

## Acceptance criteria

| Id  | Given                                                       | When                                                   | Then                                                                                                                                                                                                                                                                                                             |
| --- | ----------------------------------------------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| H1  | any API response (JSON, problem details, SSE)               | it is sent                                             | `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; base-uri 'none'`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: same-origin`, `Cross-Origin-Opener-Policy: same-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`; no `X-Powered-By` |
| H2  | `TQR_HSTS=true` (HTTPS in front)                            | any API response                                       | also `Strict-Transport-Security: max-age=63072000; includeSubDomains`; off by default (local HTTP)                                                                                                                                                                                                               |
| H3  | the built SPA served by `vite preview` or the nginx example | any page                                               | the SPA header set of `deploy/security-headers.json` (CSP `default-src 'self'; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'` + the five other headers)                                                          |
| H4  | every Playwright journey (iPhone + iPad)                    | it runs, including guest phones opened in new contexts | no CSP violation (`securitypolicyviolation` event or browser CSP console error)                                                                                                                                                                                                                                  |
| P1  | `TQR_TRUSTED_PROXIES` unset (default)                       | a client sends a spoofed `X-Forwarded-For`             | the rate-limit key stays the socket address: the third sign-in with three different headers and a limit of 2 → 429                                                                                                                                                                                               |
| P2  | `TQR_TRUSTED_PROXIES=127.0.0.1`                             | requests arrive from that proxy with `X-Forwarded-For` | the forwarded client address is the key: one client is limited, another behind the same proxy still gets through                                                                                                                                                                                                 |
| P3  | an entry that is not an address, CIDR or Express range name | the API boots                                          | it stops with `Invalid settings: TQR_TRUSTED_PROXIES…`                                                                                                                                                                                                                                                           |

## Decisions (recorded)

- **No helmet.** Six fixed headers fit in a 20-line middleware (`common/http/security-headers.ts`), first in `configureApp` so problem details, 404s and event streams get them too; no new dependency to audit. `X-Powered-By` is disabled on the Express instance.
- **Two CSPs.** The API serves no documents, so its CSP allows nothing (`default-src 'none'`). The SPA's CSP is the one from the backlog item; the built `index.html` has no inline script or style (checked), and Vue's `:style` bindings write through the CSSOM, which CSP does not block. `style-src 'unsafe-inline'` is kept as specified; dropping it is a follow-up to test, not a need proven here. No `'unsafe-eval'`: vue-i18n 11 compiles messages without `eval` (JIT), and every journey passes under the policy.
- **One source for the SPA headers**: `deploy/security-headers.json`. `vite.config.ts` reads it for `preview.headers` (not for the dev server, whose HMR needs inline code); `deploy/nginx.conf.example` repeats it and `scripts/security-headers.test.mjs` (`make test-scripts`) fails when they differ.
- **nginx example**: headers only on `location /` (nested `/assets/` uses `expires`, not `add_header`, so it inherits them); `/api/` adds none because the API sends its own (with `TQR_HSTS=true`), and it overwrites `X-Forwarded-For` with `$remote_addr` so exactly one, true address reaches the API. SSE: `proxy_buffering off`, 1 h read timeout.
- **`TQR_TRUSTED_PROXIES`**: comma-separated addresses, CIDR blocks or `loopback` / `linklocal` / `uniquelocal`, validated at boot; empty → `trust proxy` = `false`. Every limiter already keys on `request.ip`, so nothing else changed.
- **HSTS** belongs to the HTTPS terminator; the API sends it only with `TQR_HSTS=true` so a local HTTP run never pins a browser.
- **CSP guard in the journeys**: an auto fixture in `web/e2e/support/fixtures.ts` adds an init script that turns `securitypolicyviolation` into a marked console error, listens on the test's context and on every context the test creates (`browser.newContext` is wrapped for the test; `browser.newPage` goes through it), and fails the test on any CSP message. Proven by a throw-away spec that injected an inline script in a second page: both projects failed with the violation listed. `web/e2e/csp.spec.ts` (plain Playwright `test`) checks the headers on three routes and that an injected inline script and a foreign image are refused.

## Known limits / follow-ups

- The headers are verified by tests, not yet by an external scan against a real host (no deploy target yet); the checklist line stays in `docs/security.md` for the first deploy.
- `style-src 'unsafe-inline'` could probably be dropped (CSSOM writes are allowed); worth a try with the journeys as the check.
- The nginx file is an example; its syntax is not checked by `nginx -t` in CI (no nginx in the toolchain).
