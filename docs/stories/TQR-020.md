## Story

As a guest, I want to book a table online from the restaurant's link, so that I have a place when I arrive — without an account.

## Decisions (recorded)

- **Time**: Vietnam has no daylight saving, so local ↔ UTC is a fixed +7 h (`slots.ts`); instants stored in UTC, guests and staff see local dates and times.
- **Start times** every 30 minutes from opening; a slot lasts `rules.booking.slotMinutes` and must end by closing. Guests may book up to 60 days ahead.
- **Table choice**: smallest table that seats the party, ties by name; free-looking candidates are tried in that order, each insert in a savepoint; an exclusion violation (`23P01`, `bookings_no_overlap`) moves to the next candidate (ADR 0007).
- **Nearest free times**: same local day only, up to 3, closest first then earlier, returned in time order.
- **Idempotency-Key** is required (8–64 URL-safe chars, the web sends a UUID) and unique per restaurant; a replay returns 201 with the original booking regardless of the new body.
- **Rate limit**: max 5 bookings per phone per restaurant in a rolling 24 h (cancelled ones count — it is a spam guard); serialised per phone with `pg_advisory_xact_lock` so parallel requests cannot overshoot.
- **Slug** is the tenant for the public page (like the guest menu); `RestaurantStatusService.assertActive` gives the AC54 answer.
- `slot` is a generated `tstzrange(starts_at, ends_at, '[)')` column, so queries use plain timestamps while the constraint uses the range.

## Design

- API: `GET /api/g/r/:slug/slots?date=YYYY-MM-DD&party=N` → `{restaurant, date, enabled, slotMinutes, times: [{time, free}]}` (future starts only); `POST /api/g/r/:slug/bookings` + `Idempotency-Key` {date, time, partySize, name, phone, note?} → 201 `{id, status, date, time, partySize, startsAt, endsAt}` (no table: staff may move it).
- Data (migration `0005_booking`): `bookings` (composite FK to `dining_tables (restaurant_id, id)`, unique `(restaurant_id, idempotency_key)`, checks on party / name / note / slot order) + **hand-written** `CREATE EXTENSION IF NOT EXISTS btree_gist` and `bookings_no_overlap EXCLUDE USING gist (table_id WITH =, slot WITH &&) WHERE (status IN ('pending','confirmed','seated'))`.
- Code: `src/booking/domain/{slots,phone,nearest-free,booking-rules}.ts` (pure, unit-tested), `booking.service.ts`, `booking.controller.ts` (`GuestBookingController`), `booking.schema.ts`. Realtime `booking.status` on `floor` inside the transaction (ids and status only, never name or phone).
- Web: `features/booking/pages/GuestBookingPage.vue` (date, party stepper, free times only, name, phone, note; nearest-time buttons after a 409; same Idempotency-Key on a network retry), `DateField.vue`.
