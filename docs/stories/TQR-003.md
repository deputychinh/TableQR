# TQR-003: Benchmark harness and baseline

- Release: v0.2.0 · Status: doing · Owner: Claude (deliver-loop)
- Spec/design: spec "Quality targets", `benchmarks/plan.md`, design "Driving characteristics"

## Story

As the team, I want `make bench` and a committed baseline on the skeleton, so that every later item is measured against the same numbers instead of opinions.

INVEST: Independent ☑ Negotiable ☑ Valuable ☑ Estimable ☑ Small ☑ Testable ☑

## Acceptance criteria

| Id             | Given                                   | When                     | Then                                                                                                                               |
| -------------- | --------------------------------------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| AC1            | the API runs (`make dev` or `make api`) | `make bench`             | k6 runs the API workload, prints p95, fails (non-zero) when p95 > 300 ms or errors > 1 %, and writes `benchmarks/results/api.json` |
| AC2            | a production web build                  | `make ci`                | a bundle budget check fails when initial JS > 150 kB gzip (sum of entry + its static imports) and prints the size                  |
| AC3            | the preview build                       | `make lighthouse`        | Lighthouse (mobile, simulated slow 4G) records LCP and fails when LCP > 2.5 s                                                      |
| AC4            | the runs above on the owner's Mac       | the baseline is recorded | `benchmarks/baseline.json` holds the numbers with machine, date and commit; `benchmarks/plan.md` baseline column filled            |
| AC5 (negative) | the API is not running                  | `make bench`             | it stops with a clear message instead of a wall of k6 errors                                                                       |

## Non-functional

- No network beyond localhost; no telemetry upload (Lighthouse `--no-enable-error-reporting`).

## Out of scope

- Realtime and rush-replay workloads (TQR-016), order-submit workload (TQR-012 adds it to `bench/api.js`).

## References

- web.dev Core Web Vitals thresholds (LCP ≤ 2.5 s at p75); k6 thresholds docs; `benchmark` skill part B.

## Design

- `bench/api.js` k6 script (GET `/api/health` until order submit exists), thresholds, `handleSummary` → JSON.
- `web/scripts/bundle-budget.mjs` reads `dist/.vite/manifest.json`, gzips the entry chunk and its static imports, compares to 150 kB; `build.manifest: true`.
- `make lighthouse` builds, starts preview on 4310, runs `lighthouse` with Playwright's Chromium, checks LCP.
- `scripts/record-baseline.mjs` merges results into `benchmarks/baseline.json`.

## QA

These are scripts, checked by running them and by forcing each to fail (no unit tests: their logic is a threshold comparison).

| AC  | Check                                                                                                                                                           | Result |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| AC1 | `make bench` with the dev API up → `api-health p95=18.22 ms … errors=0`, exit 0, `benchmarks/results/api.json` written                                          | pass   |
| AC2 | `make budget` → `ok initial JS 52.6 kB`; `JS_BUDGET_KB=10 node web/scripts/bundle-budget.mjs` → `FAIL`, exit 1; budget runs in `make ci` and the GitHub web job | pass   |
| AC3 | `make lighthouse` ×3 → LCP 1 650 / 1 678 / 1 869 ms, exit 0; `LCP_BUDGET_MS=10` → exit 1                                                                        | pass   |
| AC4 | `make baseline` → `benchmarks/baseline.json` (machine, date, commit); `benchmarks/plan.md` baseline section                                                     | pass   |
| AC5 | `k6 run --env BASE_URL=http://127.0.0.1:3999 bench/api.js` → "API not reachable at …/api/health (status 0). Start it with: make dev", non-zero exit             | pass   |
